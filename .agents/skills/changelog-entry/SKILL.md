# Changelog entry

1. Read the top of CHANGELOG.md and copy its structure, tense and level of detail.
2. Add one entry per user-visible change, under the unreleased heading if there is one.
3. Do not change the version or tag a release unless asked.
4. Keep internal refactors out unless they change behavior.
